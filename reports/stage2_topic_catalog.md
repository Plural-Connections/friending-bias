window=8, stride=4 — the docs recommend a window of "between 4 and 8," and specifically for large corpora: "we can set stride=4 and window=8... this increases the computational speed quite a bit." Our corpus (92,902 docs, up to ~19,000 words each) is exactly that large-dataset case.

batch_size=200 (smaller than the docs' own batch_size=500 example) — the parameter exists because "a large list of token sets... might not fit into memory anymore," and our documents (up to ~900 concatenated reviews) are far heavier than the single-paragraph documents in that example, so I sized batches down accordingly.

Left use_embedding_model=False — "we compare the c-TF-IDF calculations between the token sets and all topics... this is quite fast," versus the embedding-model alternative which is "computationally quite a bit slower," not worth it at this scale.

Left calculate_tokens=False — token-level output is "computation-wise more expensive" and exists only "for visualization purposes," which isn't the goal here (a document-level table).
